# seralith.com

The marketing site and the public documentation. Plain HTML and CSS, no
JavaScript, and no third-party requests.

The `/docs` section is generated from the repository's `docs/` folder by
`tools/sitedocs` into `site/docs/`, which is not committed. Edit the Markdown in
`docs/`, never the generated pages. Links between docs become site links, links to
other repository files point at GitHub, and `docs/rfcs/` is left out. Files under
`docs/assets/` are copied to `/docs/assets/` so a page can embed them; Markdown in
that folder is not turned into a page.

The `/blog` section is generated from the repository's `blog/` folder into
`site/blog/`, also not committed, by the same `tools/sitedocs` command. Each
post is a Markdown file with YAML front matter (`title`, `date` as
`YYYY-MM-DD`, `summary`). `README.md` is not a post. The index lists posts by
date, then title. Edit the Markdown, never the generated pages.

```sh
make site-docs
python3 -m http.server -d site 8000
```

Without pretty URLs locally, open `/docs/cli.html` rather than `/docs/cli`.

## Deployment

`.github/workflows/site.yml` deploys this directory to Cloudflare Pages:

| Trigger | Result |
| --- | --- |
| Push to `main` touching `site/`, `docs/`, or `tools/sitedocs/` | Production deploy to `seralith.com` |
| Pull request touching the same paths | Preview deploy at a unique `*.seralith.pages.dev` URL |
| Manual run (Actions → Site → Run workflow) | Deploys the selected branch |

`go run ./tools/sitedocs` renders both `docs/` and `blog/`. The workflow's
path filters do not list `blog/` yet, so a commit that changes only `blog/`
does not start a deploy. Adding `blog/**` to the `push` and `pull_request`
`paths` lists in `.github/workflows/site.yml` would. The build step does not
need a new command.

Until the repository secrets below exist, the workflow skips the deploy with a
notice instead of failing.

### One-time setup

1. **API token.** Cloudflare dashboard → My Profile → API Tokens → Create
   Token → Create Custom Token. Name it `github-actions-pages`, add the
   permission **Account → Cloudflare Pages → Edit**, limit it to your account,
   and create it.
2. **Account ID.** Cloudflare dashboard → Workers & Pages. The Account ID is in
   the right-hand sidebar.
3. **Secrets.** GitHub → `seralith` → Settings → Secrets and variables →
   Actions → New repository secret: `CLOUDFLARE_API_TOKEN` and
   `CLOUDFLARE_ACCOUNT_ID`.
4. **First deploy.** Actions → Site → Run workflow on `main`. The workflow
   creates the `seralith` Pages project if it doesn't exist.
5. **Domain.** Cloudflare → Workers & Pages → `seralith` → Custom domains → Set
   up a custom domain → `seralith.com`, then again for `www.seralith.com`.
   Because the domain's DNS is already on Cloudflare, the records and
   certificates are created automatically.

If the organization restricts which actions may run, allow `cloudflare/*` under
Settings → Actions → General.

## Files

| File | Purpose |
| --- | --- |
| `index.html`, `styles.css` | The landing page |
| `security.html` | Vulnerability disclosure policy, served at `/security` |
| `404.html` | Served for unknown paths |
| `_headers` | Security headers (CSP, HSTS, framing, referrer, permissions) and caching |
| `.well-known/security.txt` | RFC 9116 security contact; renew `Expires` before 2027-11-25 |
| `robots.txt`, `sitemap.xml` | Crawler guidance; the docs sitemap is generated at `docs/sitemap.xml` |
| `docs/` | Generated by `tools/sitedocs` from the repository's `docs/`; not committed |
| `blog/` | Generated by `tools/sitedocs` from the repository's `blog/`; not committed |
| `favicon.*`, `apple-touch-icon.png`, `logo.svg`, `og-image.png` | Generated from `brand/`; do not edit by hand |

The Content-Security-Policy forbids scripts and inline styles. Keep styles in
`styles.css`.
Every page wraps its body in `<!--email_off-->` markers so Cloudflare's email
obfuscation leaves addresses alone; its decoder is a script the policy blocks.
Keep the markers on new pages.
